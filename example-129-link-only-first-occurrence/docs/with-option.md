## First paragraph

When you build an **API**, you define a contract between a client and a server.
A well-designed API is consistent, predictable, and documented.

## Second paragraph

Revisiting the topic: building a good API requires careful versioning.
Good API design also considers backward compatibility.
Every public API should have a changelog.

## Third paragraph

The deploy step publishes the API to a target environment.
After a successful deploy, consumers can call the API endpoints.
Automated tests run on every deploy to catch regressions.

## Summary

REST is a popular architectural style for APIs. REST is stateless by design.
Using a webhook alongside REST can decouple producers from consumers.
A webhook fires when an event occurs, so consumers do not need to poll.
